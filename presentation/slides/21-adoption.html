Organisation · adoption

Un atelier en deux temps, un déploiement en trois vagues

L'outil est prêt. Ce qui reste à organiser, c'est le passage de main : former sur un cas réel, puis élargir progressivement plutôt que basculer toute l'équipe d'un coup.

Plan de formation
PublicContenu
Tout le monde Concepts, puis prise en main guidée du plugin sur un cas réel : checklist « Mon travail », premier point de sauvegarde, puis le flux quotidien sujet → enregistrement → push → Merge Request.
Futurs intégrateurs Release et hotfix, résolution de conflits, mode développeur. C'est le module qui répartit le rôle d'Intégrateur au-delà d'une seule personne.
Support Fiche mémo, plus un créneau de questions après la formation — au moment où les vraies questions apparaissent, pas pendant l'atelier.
Aucun build côté utilisateur. Le plugin tourne dans le processus principal d'Electron : copier le dossier dans le répertoire plugins de Camunda Modeler, puis npm install.
Déploiement — trois vagues

Vague 1 — Pilote

Un à deux volontaires, sur de vraies méthodes. L'objectif n'est pas de valider l'outil mais de trouver ce qui coince dans le contexte réel de l'équipe.

Vague 2 — Ajustements

Corrections issues du pilote, sur le plugin comme sur la configuration partagée du projet. C'est aussi là que le vocabulaire de l'interface se cale sur celui de l'équipe.

Vague 3 — Généralisation

Déploiement à toute l'équipe, accompagné de la formation. Les pilotes deviennent les premiers relais de support.
